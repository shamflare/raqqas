## 0. الخلاصة في سطرين

بعد إتمام الإعداد لمرة واحدة (القسم 3)، كل إصدار جديد = **أمر واحد**:

```bash
bash deploy/14-release.sh --bump patch --track internal --notes "ما الذي تغيّر"
```

كل ما تحت هذا السطر شرحٌ لِما يفعله هذا الأمر، ولِما يحتاجه مرة واحدة قبله.

## 1. الفرق بين النسختين — أهمّ فكرة في الملف

نحن ننتج **نسختين مختلفتين** من التطبيق نفسه:

| | نسخة الموقع | نسخة المتجر |
|---|---|---|
| الملف | `.apk` | `.aab` (Play يرفض apk للتطبيقات الجديدة) |
| السكربت | `09-build-apk.sh` | `12-build-aab.sh` |
| المتغيّر | `EXPO_PUBLIC_DISTRIBUTION=direct` | `EXPO_PUBLIC_DISTRIBUTION=play` |
| زرّ التحديث | ينزّل ملف APK من موقعنا | يفتح صفحة المتجر |

**لماذا هذا الفصل ضروري؟** سياسة «إساءة استخدام الجهاز والشبكة» لدى Google
تمنع منعًا باتًّا أن يُنزّل تطبيقٌ منشور في المتجر حزمةَ تثبيت من خارجه.
عقوبتها **إزالة التطبيق** لا مجرّد رفض تحديث.

ولهذا لم نجعل الأمر شرطًا يقرأه التطبيق من الخادم: المراجع يقرأ **الكود**.
القيمة تُحقن وقت البناء، فحزمة المتجر لا تحوي مسار التنزيل أصلًا
(`app/src/config.ts` → `CAN_DOWNLOAD_APK`).

> ⚠️ القيمة الافتراضية في الكود هي `play` عمدًا: لو نُسي المتغيّر في بناء ما،
> يقع الخطأ في الاتجاه الآمن (تطبيق يحيل إلى المتجر) لا في اتجاه المخالفة.

## 2. ما أنجزناه في الكود (لا تكرّره)

هذه كلها **متطلبات إلزامية** أُنجزت وتحرسها اختبارات في
`backend/tests/test_play_requirements.py`:

| المتطلَّب | أين |
|---|---|
| حذف الحساب داخل التطبيق | «حسابي ‹ حذف حسابي» → `DELETE /auth/me/delete` |
| حذف الحساب من الويب | `https://souq.syrz1.com/delete-account` |
| سياسة الخصوصية | `https://souq.syrz1.com/privacy` |
| شروط الاستخدام + قائمة الممنوع | `https://souq.syrz1.com/terms` |
| الإبلاغ عن إعلان | زرّ 🚩 في كل إعلان |
| حظر معلن ورفع الحظر | زرّ 🚫 + «حسابي ‹ المحظورون» |
| مراجعة بشرية قبل النشر | لوحة الإدارة ‹ صفّ المراجعة |
| صلاحيات نظيفة | `app.json` → `blockedPermissions` |

**لا تُعد `CAMERA` أو `READ_MEDIA_IMAGES` إلى `app.json`.** التطبيق يختار الصور
عبر «منتقي صور أندرويد» الذي لا يحتاج أي صلاحية، ووجودها يفرض نموذج إقرار
إضافيًا في الكونسول بلا مقابل. الاختبار
`test_app_declares_no_sensitive_android_permissions` يمنع عودتها.

## 3. الإعداد لمرة واحدة

### 3.1 مفتاح التوقيع — أخطر خطوة في الملف

المفتاح موجود على الخادم منذ أول بناء APK:

```
/etc/souq/keystore/souq-release.jks     المفتاح
/etc/souq/keystore.env                  كلمات مروره
```

**القرار المتَّخذ:** نرفع هذا المفتاح ليكون **مفتاح توقيع التطبيق** لدى Google،
لا أن يولّد غوغل مفتاحًا جديدًا.

**السبب:** أندرويد يرفض تحديث تطبيق بتوقيع مختلف. من ثبّت APK من موقعنا سيجد
تحديث المتجر مرفوضًا، ويحتاج حذف التطبيق وإعادة تثبيته — وسيخسر تسجيل دخوله.

**خذ نسخة احتياطية الآن إن لم تكن فعلت:**

```bash
scp -i ~/.ssh/souq_raqqa root@46.224.188.126:/etc/souq/keystore/souq-release.jks .
scp -i ~/.ssh/souq_raqqa root@46.224.188.126:/etc/souq/keystore.env .
```

> ⚠️ ضياع هذا المفتاح = **استحالة تحديث التطبيق لأي مستخدم إلى الأبد**.
> لا حلّ إلا نشر تطبيق جديد وخسارة كل من ثبّت القديم.
> احفظه في مكانين لا يفشلان معًا. ولا يُرفع إلى Git أبدًا.

**خطوات رفعه إلى Google** (تُنفَّذ مرة واحدة عند إنشاء التطبيق في الكونسول):

1. في الكونسول: **Create app** → املأ الاسم واللغة واختر «App» و«Free».
2. **Release ‹ Setup ‹ App integrity ‹ App signing**.
3. اختر **Export and upload a key from Java keystore**.
4. نزّل أداة `pepk.jar` من الصفحة نفسها، وانقلها إلى الخادم:
   ```bash
   scp -i ~/.ssh/souq_raqqa pepk.jar root@46.224.188.126:/root/
   ```
5. على الخادم — الصق `--encryption-key` الظاهر في صفحة الكونسول:
   ```bash
   ssh -i ~/.ssh/souq_raqqa root@46.224.188.126
   . /etc/souq/keystore.env
   java -jar /root/pepk.jar \
     --keystore=/etc/souq/keystore/souq-release.jks \
     --alias="$KEY_ALIAS" \
     --output=/root/souq-upload-key.zip \
     --include-cert \
     --encryptionkey=<الصق المفتاح من الكونسول>
   ```
   يطلب كلمتَي مرور — كلتاهما في `/etc/souq/keystore.env`.
6. نزّل `souq-upload-key.zip` وارفعه في الكونسول.

### 3.2 حساب الخدمة — ليعمل الرفع الآلي

بلا هذا يبقى الرفع يدويًا بسحب الملف في المتصفّح كل مرة.

1. **Google Cloud Console** → أنشئ مشروعًا (أو استعمل موجودًا).
2. فعّل **Google Play Android Developer API**.
3. **IAM ‹ Service Accounts** → أنشئ حسابًا → **Keys ‹ Add key ‹ JSON** → نزّله.
4. **Play Console ‹ Users and permissions ‹ Invite new user** → الصق بريد حساب
   الخدمة → امنحه على التطبيق: `Release to testing tracks` و`Release to production`.
5. ضع الملف على الخادم بصلاحيات ضيّقة:
   ```bash
   scp -i ~/.ssh/souq_raqqa play-service-account.json root@46.224.188.126:/etc/souq/
   ssh -i ~/.ssh/souq_raqqa root@46.224.188.126 \
     "chmod 600 /etc/souq/play-service-account.json && chown root:root /etc/souq/play-service-account.json"
   ```

> الملف في `/etc/souq/` لا في مجلد الكود — كبقية أسرارنا. رفع الكود لا يمسّه،
> ولا يمكن أن يُنشر في Git بالخطأ.

6. ثبّت مكتبة العميل مرة واحدة:
   ```bash
   ssh -i ~/.ssh/souq_raqqa root@46.224.188.126 \
     "/srv/souq/venv/bin/pip install -q google-api-python-client google-auth"
   ```

### 3.3 أول رفع — يدوي بالضرورة

**الرفع الآلي لا يعمل قبل أن تُنشئ أول إصدار يدويًا.** واجهة Play API لا تقبل
حزمة لتطبيق لم يُملأ سجلّه بعد. فالمرة الأولى:

```bash
bash deploy/12-build-aab.sh https://souq.syrz1.com
scp -i ~/.ssh/souq_raqqa root@46.224.188.126:/srv/souq/aab/souq-raqqa-latest.aab .
```

ثم اسحب الملف في **Play Console ‹ Testing ‹ Internal testing ‹ Create release**.

## 4. الإصدارات التالية — أمر واحد

```bash
# تصحيح خطأ:      1.3.0 → 1.3.1
bash deploy/14-release.sh --bump patch --track internal --notes "إصلاح لوحة المفاتيح"

# ميزة جديدة:      1.3.1 → 1.4.0
bash deploy/14-release.sh --bump minor --track internal --notes "مبدّل العملة"

# النشر للجميع بعد نجاح الاختبار
bash deploy/14-release.sh --track production --notes "..." --no-build
```

ما يفعله بالترتيب:

1. يرفع `version` و`versionCode` في `app/app.json`
   — **Play يرفض `versionCode` مكرّرًا**، وهذا أكثر سبب فشل شائع.
2. يرفع كود التطبيق إلى الخادم.
3. يبني `.aab` موقّعًا بقيمة `DISTRIBUTION=play`.
4. يرفعه إلى المسار المطلوب عبر Play API.
5. يطبع رابط الإصدار في الكونسول.

### المسارات (tracks)

| المسار | متى |
|---|---|
| `internal` | فورًا، حتى 100 مختبِر، بلا انتظار مراجعة — **ابدأ به دائمًا** |
| `closed` | الاختبار المغلق المطلوب للحسابات الشخصية (القسم 6) |
| `open` | اختبار مفتوح لأي أحد |
| `production` | النشر العام |

## 6. عقبات معروفة — اقرأها قبل أن تتفاجأ

### 6.1 شرط الاختبار المغلق للحسابات الشخصية

حسابنا **شخصي** (`lebid hacalaye` · معرّف `7344012876268681786`). غوغل يفرض على
الحسابات الشخصية المُنشأة حديثًا اختبارًا مغلقًا قبل السماح بالنشر العام —
والعدد والمدة تغيّرا أكثر من مرة، فلا تعتمد على رقم محفوظ.

**تحقّق بنفسك، لا تخمّن:**
`Play Console ‹ Test and release ‹ Testing ‹ Closed testing` — إن كان الشرط
مفروضًا فستجد لوحة تعدّ المختبِرين والأيام المتبقية. وإن لم تجدها فالشرط لا
ينطبق على حسابك.

**إن كان مفروضًا:** يلزم عدد من المختبِرين يقبلون الدعوة ويبقون مسجّلين مدة
متصلة. اجمعهم عبر:
- رابط الاشتراك الذي يولّده الكونسول (Opt-in URL) — يُرسل في واتساب.
- أو مجموعة بريد Google تضيف إليها عناوينهم.

يكفي أن يقبلوا الدعوة ويثبّتوا التطبيق — ولا يلزم استعماله يوميًا. لكن **من
يلغي اشتراكه يقطع العدّاد**، فأخبرهم بذلك صراحةً.

**البديل:** الحساب المؤسسي (Organization) لا يخضع لهذا الشرط، لكنه يحتاج سجلًّا
تجاريًا و`D-U-N-S`. لا يستحق العناء إلا إن تعذّر جمع المختبِرين.

#### ما تعلّمناه فعلًا أثناء جمع المختبِرين (2026-08-20 → 09-05)

دُعي 11 فقبِل 5 في أول يوم. الستّة الباقون تعثّروا لأسباب كلّها من هذه الأربعة:

1. **الرابط الخطأ.** أرسلنا `play.google.com/store/apps/details?id=…` فظهر لهم
   «لم يتم العثور على العنصر». رابط الاشتراك هو
   **`https://play.google.com/apps/testing/com.souqraqqa.app`** — من
   `Testers ‹ How testers join your test ‹ Join on the web ‹ Copy link`.
   رابط المتجر لا يعمل إلا **بعد** الضغط على «Become a tester».
2. **حساب غوغل مختلف.** يعطيك بريدًا وهاتفه مسجَّل ببريد آخر. اطلب منه أن يقرأ
   البريد من **الصورة الدائرية أعلى صفحة الاشتراك** ويرسله كما هو — لا من ذاكرته.
   ونفس الحساب يجب أن يكون مسجَّلًا في تطبيق Play على الهاتف لا في المتصفّح فقط.
3. **دولة غير مستهدَفة.** المسار محصور بقائمة دول (`Countries / regions`). من
   يسكن خارجها يرى «لم يتم العثور على العنصر» نفسها. وسّع القائمة — اختبار مغلق
   لا يراه إلا من في قائمة البريد، فالتوسيع بلا ضرر.
4. **التأخير.** العدّاد في `Dashboard ‹ Production` يتحدّث دوريًا وقد يتأخّر
   حتى 24 ساعة. لا تحكم على النتيجة في نفس الساعة.

**زرّ `Save` الرمادي أسفل صفحة Testers لا يعني عطلًا** — يعني أن لا شيء غير
محفوظ. غوغل يفعّله فقط بعد تغيير.

**ادعُ 16–18 لا 12.** النسبة عندنا كانت أقلّ من النصف يُتمّون الخطوات، ومن
ينسحب بعد بدء العدّ الزمني يعيد الأربعة عشر يومًا من الصفر.

**العدد لا الأسماء:** الكونسول يعطيك رقم المشتركين فقط
(`Dashboard ‹ Production ‹ N testers currently opted-in`) ولا يخبرك من قبِل.
لمعرفة المتعثّرين اسأل كلًّا منهم مباشرة.

### 6.2 التحقق من هوية المطوّر

بند **Android developer verification** في الشريط الجانبي. أكمله مبكرًا — بلا
إتمامه يُمنع النشر مهما كان التطبيق جاهزًا.

### 6.3 حساب المراجع

الدخول عندنا برقم هاتف، والمراجع لا يملك رقمًا سوريًا. **أنشئ حسابًا تجريبيًا
واتركه دائمًا** واكتب بياناته في **App content ‹ App access**. بلا هذا يرى
المراجع شاشة دخول لا يستطيع تجاوزها، والنتيجة رفض بسبب «لم نتمكن من فحص
التطبيق».

### 6.4 لا تنسَ رفع versionCode

Play يرفض حزمة بـ`versionCode` سبق رفعه، ولو أُلغي إصداره. السكربت `14-release.sh`
يتكفّل بذلك — لكن إن بنيت يدويًا فارفعه بيدك.
