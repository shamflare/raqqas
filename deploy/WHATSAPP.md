# واتساب — إيصال رموز استعادة كلمة المرور

> من نسي كلمة مروره يطلب رمزًا، فيصله على واتساب. هذا الملف يشرح كيف يُرسَل
> الرمز فعلًا، وما ثمن الطريقة المختارة.

---

## ⚠️ اقرأ هذا أولًا

الطريقة المفعَّلة اليوم **غير رسمية**. الخادم يشغّل خدمة تتصل بواتساب كأنها
«جهاز مرتبط» (مثل واتساب ويب)، ويرسل الرسائل من رقم واتساب عادي.

**هذا مخالف لشروط استخدام واتساب، وMeta قد تحظر الرقم — أحيانًا بلا إنذار.**

ما نفعله للتقليل من الخطر:

| الوقاية | أين |
|---|---|
| ثلاث رسائل في الساعة للحساب الواحد كحدّ أقصى | `PasswordResetCode.MAX_PER_HOUR` |
| حدّ لكل عنوان IP فوق ذلك | `ResetThrottle` في `accounts/views.py` |
| فاصل عشوائي بين رسالتين متتاليتين | `MIN_GAP_MS` في `wa-bot/index.js` |
| رسالة قصيرة **بلا أي رابط** | `RESET_MESSAGE` في `notifications/whatsapp.py` |
| لا رسائل جماعية ولا تسويق — رموز فقط | القرار نفسه |

**القاعدة العملية:** استعمل **رقمًا مخصّصًا للتطبيق**. لا رقمك الشخصي، ولا رقمًا
يخسر بضياعه شيء. شريحة رخيصة تكفي.

**المخرج حين يحين وقته:** الكود يدعم Meta WhatsApp Cloud API الرسمي، والتحويل
إليه **تبديل متغيّر بيئة واحد** (انظر آخر الملف). لا إعادة كتابة، ولا تحت ضغط
رقم محظور.

## التنصيب

```bash
# على جهازك: ارفع الكود
scp -i ~/.ssh/souq_raqqa -r deploy/wa-bot root@46.224.188.126:/srv/souq/
scp -i ~/.ssh/souq_raqqa deploy/15-wa-bot.sh root@46.224.188.126:/root/

# على الخادم
bash /root/15-wa-bot.sh
```

السكربت يولّد رمزًا مشتركًا، ويكتبه في `/etc/souq/app.env` ليقرأه Django،
ويسجّل خدمة systemd تُقلع تلقائيًا وتُعاد عند السقوط.

### الربط — من لوحة الإدارة

> **لوحة الإدارة ← 💬 واتساب**

الصفحة تعرض رمز QR وتحدّث نفسها كل ثانيتين. على هاتف الرقم المخصّص:

> واتساب ← ⋮ ← **الأجهزة المرتبطة** ← **ربط جهاز** ← امسح الرمز

أول ما ينجح المسح تنقلب الشاشة إلى «متصل» وتعرض الرقم. وفيها زرّ **رسالة
تجريبية** يحسم الفرق بين «مربوط» و«يرسل فعلًا»، وزرّ **فكّ الربط** لتبديل
الرقم أو حين يُحظر الحالي.

**لماذا من اللوحة لا من الطرفية:** الربط يحتاج هاتفًا في يد صاحب الرقم،
وصاحب الرقم ليس بالضرورة من يملك مفتاح SSH. وحين ينقطع الربط — والانقطاع
وارد على هذا المسار — يجب أن تكون إعادته ضغطةَ زرّ لا جلسةَ طرفية.

**البديل من الطرفية** (إن تعذّر الوصول إلى اللوحة):

```bash
systemctl stop souq-wa
cd /srv/souq/wa-bot && sudo -u souq -H npm run pair
systemctl start souq-wa
curl -s http://127.0.0.1:8787/health     # {"ready":true}
```

الجلسة تُحفظ في `/etc/souq/wa-session/` ولا تحتاج مسحًا ثانيًا — **ولا تُحذف**:
حذفها يقطع الإرسال حتى تعيد المسح. وهي **سرّ بحجم مفتاح**: من نسخها انتحل
واتساب الرقم كاملًا، لا مجرّد إرسال رسائل.

## الفحص

```bash
# هل الخدمة متصلة؟
curl -s http://127.0.0.1:8787/health

# رسالة تجريبية إلى رقمك
source /etc/souq/wa-bot.env
curl -s -X POST http://127.0.0.1:8787/send \
     -H "X-Bot-Token: $WA_BOT_TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"to":"963944567890","text":"تجربة من سوق الرقة"}'

# المسار كاملًا من طرف المستخدم
curl -s -X POST https://souq.syrz1.com/api/v1/auth/password/forgot \
     -H 'Content-Type: application/json' \
     -d '{"phone":"+963944567890"}'

# السجلّات
journalctl -u souq-wa -f
```

الخدمة **لا تسجّل نصّ الرسالة** — فيه رمز الاستعادة، ولا مكان له في سجلّ خادم.

## حين يتعطّل

| العرض | السبب الغالب | العلاج |
|---|---|---|
| اللوحة تعرض «غير مربوط» | الربط انتهى أو أُلغي من الهاتف | امسح الرمز الظاهر في اللوحة |
| في السجلّ: `انتهى الربط نهائيًا` | الرقم محظور، أو أُزيل الجهاز المرتبط | جرّب الربط؛ إن فشل فالرقم محظور — استعمل رقمًا آخر |
| المستخدم يرى «تعذّر إرسال الرمز» | الخدمة ساقطة أو غير مرتبطة | `systemctl status souq-wa` ثم السجلّ |
| الرسائل تصل ثم تتوقف فجأة | حظر آلي بسبب معدّل الإرسال | أوقف الخدمة يومًا، وراجع الحدود أعلاه |
| السجلّ: `رمز الاستعادة لم يُرسل فعلًا` | `WHATSAPP_PROVIDER=log` | شغّل `15-wa-bot.sh` فهو يضبطه إلى `bot` |

**المستخدم لا يُكذَب عليه أبدًا:** حين يفشل الإرسال تعيد الواجهة «تعذّر إرسال
الرمز الآن» ولا تقول «أرسلنا» — ويُحرَق الرمز فلا يبقى صالحًا بلا أن يعرفه أحد.

## المتغيّرات

كلّها في `/etc/souq/app.env` (يقرأها Django) و`/etc/souq/wa-bot.env` (تقرأها الخدمة).

| المتغيّر | المعنى |
|---|---|
| `WHATSAPP_PROVIDER` | `bot` · `cloud` · `log` |
| `WHATSAPP_BOT_URL` | `http://127.0.0.1:8787` |
| `WHATSAPP_BOT_TOKEN` | الرمز المشترك — يولّده السكربت |
| `WA_SESSION_DIR` | `/etc/souq/wa-session` |

`log` يعني: لا إرسال، والرمز يُكتب في سجلّ الخادم وحده. مفيد للتطوير، وهو
الافتراضي حتى لا يدّعي خادم بلا إعداد أنه يرسل.

## التحويل إلى المسار الرسمي

يوم يستحقّ التطبيق نفقة صغيرة، أو يوم يُحظر الرقم مرّة أخيرة:

1. أنشئ حساب **Meta Business** وأضف تطبيق WhatsApp، واحصل على `Phone number ID`
   ورمز وصول دائم.
2. اعتمد قالبًا من فئة **Authentication** باسم `password_reset` وبمعامل واحد
   (الرمز). رسالة يبدأها العمل خارج نافذة 24 ساعة لا تمرّ إلا بقالب معتمَد.
3. في `/etc/souq/app.env`:

   ```
   WHATSAPP_PROVIDER=cloud
   WHATSAPP_CLOUD_TOKEN=...
   WHATSAPP_CLOUD_PHONE_ID=...
   WHATSAPP_CLOUD_TEMPLATE=password_reset
   WHATSAPP_CLOUD_TEMPLATE_LANG=ar
   ```

4. `systemctl restart souq && systemctl disable --now souq-wa`

**لا تعديل في الكود.** `CloudSender` مكتوب ومختبَر في
`backend/apps/notifications/whatsapp.py`، والتبديل يمرّ بـ`get_sender()` وحدها.

الثمن: رسائل فئة Authentication **ليست مجانية** (سنتان تقريبًا للرسالة، يختلف
بالبلد). في المقابل: لا حظر، ولا ربط ينتهي، ولا رقم يُفقد.
